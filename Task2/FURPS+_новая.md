| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| F   | Функциональные (Functionality)     |              |
| F1  | Подать заявку на депозит с сайта   | Клиент оставляет Ф.И.О. и телефон; заявка попадает в систему кол-центра. |
| F2  | Подать заявку на депозит через интернет-банк | Клиент авторизуется, видит список депозитов и персонализированную ставку; выбирает счет и сумму, подтверждает через SMS-код. |
| F3  | Передача заявок в бэк-офис для обработки (MVP) | В MVP бэк-офис обрабатывает заявку вручную в АБС; система должна создавать запись в АБС и уведомлять клиента SMS. |
| F4  | Управление и хранение ставок депозитов | Ставки не в XLS: централизованное хранилище ставок (АБС или отдельный сервис), доступное департаментам депозитов и кредитов. |
| F5  | Предодобренные предложения по кредиту (задание на будущее) | Видны в интернет-банке; при заполнении дополнительных полей — запрос скоринга. |
| U   | Удобство использования (Usability) |              |
| U1  | Привычный UI/дизайн (brand)       | Соответствие корпоративной системе дизайна; согласованные цвета/элементы. |
| U2  | Быстрый отклик интерфейса          | Все клиентские операции — отклик миллисекунды; ощущение «мгновенности». |
| U3  | Понятные сообщения и статусы       | Пользователь видит статус заявки (принята, требуются документы, обработана). |
| R   | Надёжность (Reliability)           |              |
| R1  | Доступность 99.9%                  | Сервисы интернет-банка и скоринга/конвейера должны быть доступны 24/7. Для критичных сторон — SLA. |
| R2  | Изоляция нагрузки АБС              | Не допускать прямой высокой нагрузки интернет-банка на АБС — использовать промежуточный слой/очереди/кэш. |
| R3  | Гарантированная доставка уведомлений (SMS) | Уведомления о подтверждении ставки и открытии депозита должны отправляться и ретранслироваться при ошибках шлюза. |
| P   | Производительность (Performance)   |              |
| P1  | Быстрое чтение справочных данных   | Справочные данные должны грузиться <200–300 ms; критично для UX. Можно кэшировать. |
| P2  | Горизонтальное масштабирование интернет-банка | База интернет-банка — MS SQL; предусмотреть шардинг/реплики и балансировщик. |
| P3  | Вертикальные ограничения АБС       | АБС масштабируется вертикально; предусмотреть отложенные операции и буферизацию запросов. |
| S   | Поддерживаемость (Supportability)  |              |
| S1  | Использование существующих технологий | MS SQL, Oracle, Java, Python/Flask, .NET — приоритет; новые компоненты должны быть совместимы. |
| S2  | Документация и API контракт        | Описаны API для взаимодействия (JSON/REST), схема обмена файлов для партнёрского кол-центра. |
| S3  | Мониторинг и алерты                | Метрики производительности, журнал ошибок, SLO/SLA и каналы оповещения для команд поддержки. |
| +R  | + Ограничения (Restrictions)       |              |
| +R1 | Нельзя напрямую нагружать АБС      | Из-за перегрузки БД АБС — ограничить прямые онлайн-запросы. |
| +R2 | Партнёрский кол-центр принимает только файлы | Нельзя реализовывать API-вызовы с партнёром — только файловая передача (SFTP/CSV). |
| +R3 | SMS-шлюз — внешний (оператор)      | Необходимо учитывать задержки и вероятность отказов; минимизировать зависимости ядра системой очередей. |
| +R4 | Нормативная идентификация клиентов | Новых клиентов нельзя полностью дистанционно идентифицировать — требуется визит в отделение. |
